## 全文剪藏
你有没有试过写了一篇“神笔之作”的 Obsidian 笔记，结果想分享给别人却不知道该怎么搞？要么复制粘贴，要么截图整篇，整得跟PPT一样累。更别说你还想更新一下内容，那只能一边修改一边发微信截图，活脱脱成了笔记工具界的“社恐刑天”。那有没有一种办法，既能优雅地分享笔记内容，又能随时同步更新，还能让你控制隐私权限？

鬼哥今天就要给你掏出来一个宝藏插件 —— **Share as Gist** ，它能让你一键把 Obsidian 里的笔记分享到 GitHub Gist，支持公开也支持私密，还能自动同步，简直是内容创作者的梦中情“Gist”！

### 插件是干嘛的？

咱们先说人话：这个插件的作用就一句话——**把你的 Obsidian 笔记内容变成 GitHub Gist，并支持自动更新和隐私控制** 。

讲真，它解决了几个非常“烦人但真实”的问题：

1. 1\. **笔记分享超麻烦** ：截图？导出PDF？复制markdown？全都太笨重了。
2. 2\. **同步更新不方便** ：你改了笔记，别人看的是旧版，心态直接炸裂。
3. 3\. **链接难管理** ：写了10篇笔记，每篇都想单独分享？直接开个 gist 多香。

这个插件就像是你和 GitHub Gist 之间的翻译器，帮你把 Obsidian 里的笔记一键发布，分享到网络上。而且你可以选择是公开的、私密的，还是企业版 GitHub，统统支持！

你以为它只是一个“分享笔记”的小工具？错！这个插件可以说是为内容创作者量身打造的终极分享神器，功能直接拉满：

* • 🔒 **隐私控制** ：想公开就公开，想私密就私密，谁也管不着你。
* • 💼 **支持 GitHub 企业版** ：公司内部也能用，文档协作无压力。
* • 🔄 **更新同步** ：开启自动保存之后，改完笔记自动同步 Gist，完全不用操心。
* • 🗑️ **可删可管** ：改主意了？一个指令删掉 Gist，干干净净。
* • 📜 **支持目录生成** ：让你的 Gist 看起来更专业，有结构。

### 插件怎么下载、咋装？

好，讲完背景我们来实操。

#### 下载 & 安装步骤：

1. 1\. 打开 Obsidian。
2. 2\. 进入设置 → Community Plugins（社区插件）→ 浏览。
3. 3\. 搜索 **Share as Gist** ，点击 Install 安装。
4. 4\. 安装完之后，点击 Enable 启用插件。

**离线安装** 

如果你无法在线安装插件，别担心，我已经把热门插件下载好了

点击下方公众号，回复关键字：**Obsidian** ，获取Obsidian资料合集。

记住，安装只是开始，关键的是——**配置 GitHub 访问权限** ！

### 怎么配置 GitHub 的权限？

这一步比较关键，需要你搞一个 GitHub 的“访问令牌”（Personal Access Token，简称 PAT）。

#### 创建 GitHub PAT：

1. 1\. 登录你的 GitHub 账户。
2. 2\. 创建一个 Token，勾选 `gist` 权限（这是访问 Gist 的关键）。
3. 3\. 复制 Token（只能复制一次，别搞丢了）。

如果你用的是 GitHub Enterprise 版本，公司内部的地址，记得使用自定义 API 地址，格式如下：


```
https://你的企业域名/api/v3
```


#### 在 Obsidian 设置插件：

1. 1\. 打开 Settings → Share as Gist。
2. 2\. 选择 GitHub.com 或 Enterprise，根据你的情况来。
3. 3\. 粘贴你的 Token 到对应的框里。
4. 4\. 如果用企业版，别忘了加上 API URL。

配置完成，万事俱备！

### 怎么用？一键发布 Gist！

配置好之后，直接上干货操作：

#### 创建 Gist：

1. 1\. 打开 Command Palette（快捷键 Cmd/Ctrl + P）。
2. 2\. 输入 `gist`，你会看到两个命令：
   * • Share as **Public**  Gist
   * • Share as **Private**  Gist
3. 3\. 选择一个，按回车。
4. 4\. 可以自定义描述（Description），也可以直接回车跳过。
5. 5\. Done！你的笔记就已经变成了一个 Gist，链接已复制到剪贴板。

就这么快！比微信发截图还省事！

### 自动更新和高级设置怎么玩？

这插件的强大还不止于此，它有一大堆可以自由调教的设置，鬼哥简单说下：

#### 插件设置说明：

| 设置项                                  | 默认 | 功能解释                  |
| ------------------------------------ | -- | --------------------- |
| Enable updating gists after creation | ✅  | 自动记录 Gist 信息，方便后续更新   |
| Include front matter in gists        | ❌  | 要不要把 frontmatter 一起分享 |
| Enable auto-saving Gists after edit  | ❌  | 自动保存笔记改动并更新 Gist      |
| Enable auto-save notice              | ❌  | 每次自动保存的时候弹个提示         |
| Include table of contents            | ❌  | 给 Gist 自动生成一个目录       |

根据你的需求，自由勾选就好。比如我是个内容创作者，我就会开启自动更新、生成目录；如果是临时分享，就用默认的私密 Gist 模式更安心。

### 常用操作一览（Command Palette 里搞定一切）

| 操作         | 命令                           |
| ---------- | ---------------------------- |
| 创建 Gist    | Share as public/private gist |
| 更新 Gist    | 同上命令，再次执行即可                  |
| 复制 Gist 链接 | Copy Gist URL                |
| 打开 Gist    | Open Gist                    |
| 删除 Gist    | Delete Gist                  |

鬼哥建议大家把这些命令加进快捷键设置里，这样用起来就像按 Ctrl+C 那样顺手。

### 安全性问题，鬼哥怎么看？

这个插件确实存了一个“潜在问题”——**Token 是保存在 localStorage 里的** ，也就是说它不会被你 Vault 同步，但理论上别的 Obsidian 插件能看到。

所以我的建议是：

* • **只给 Gist 权限，不要给别的权限** 。
* • **别在公司 Vault 里乱用不熟的插件** 。
* • **定期更新 Token，防止泄露** 。

毕竟我们用插件是为了方便，不是为了多一层担忧，懂的都懂。

### 插件开发者友好吗？能自己魔改吗？

答案是 YES！

### 想自己改？流程如下：

1. 1\. clone 代码到 `.obsidian/plugins` 目录。
2. 2\. 进入该插件目录，执行：  

```
npm install
npm run dev
```

3. 3\. 在 Obsidian 里重载插件，每次改完手动刷新。
4. 4\. 改完后用 Git 提交代码，按语义版本控制。

完全开源，文档也写得不错，想玩高级玩法的朋友可以直接开整。
