## 0.6 为什么向量数据库对AI如此重要？

向量数据库对于人工智能尤其重要，原因主要包括以下几个方面：

1. **高维数据的有效管理** ：AI模型，特别是深度学习模型，通常需要处理大量的高维数据。向量数据库专为存储和管理这类数据设计，可以高效地处理和索引向量形式的数据，如图像、文本和视频中的特征向量。
2. **提升检索效率** ：在AI应用中，经常需要快速检索与输入数据相似的信息，例如在推荐系统、图像识别或自然语言处理中。向量数据库可以通过空间索引技术（如KD树、球树或乘积量化），快速找到最近邻向量，大大加快了搜索速度。
3. **支持复杂查询** ：向量数据库能够支持复杂的相似性搜索查询，这对于构建动态和互动的AI应用至关重要。用户可以根据相似性得分查询数据，使得AI系统能够更加智能和响应用户的需求。
4. **强化机器学习模型** ：通过使用向量数据库，机器学习模型可以直接访问训练和查询期间所需的向量数据，减少了预处理步骤，优化了数据流，提高了训练和推理的效率。
5. **支持大规模数据处理** ：现代AI应用常常涉及大量数据的处理。向量数据库设计有良好的可扩展性，可以处理从数百万到数十亿的数据点，支持大规模的AI应用部署。
6. **数据安全和隐私** ：在处理敏感信息时，向量数据库可以提供额外的数据安全和隐私保护措施，如加密存储和访问控制，这对于遵守数据保护法规（如GDPR）的AI应用尤为重要。

## 0.7 向量数据库是如何工作的？

向量数据库是一种专门为存储和快速检索大量高维数据（如图片、文本等）设计的数据库。这种数据库使用了特殊的技术来组织数据，使得你可以迅速找到与给定数据相似的信息。简单来说，向量数据库就像是一个超级高效的图书管理员，能快速帮你从海量数据中找到你需要的内容，非常适合支持需要快速搜索和匹配功能的人工智能应用。

向量数据库的工作原理主要基于几个核心组件和技术，这些都专门设计来有效地处理和检索高维向量数据。以下是向量数据库工作流程的关键步骤：

1. **数据表示** ：
   * 向量数据库中的数据通常表示为向量，每个向量是一个多维的数值数组。这些向量可以是从原始数据（如图像、文本或声音文件）通过某种算法（例如深度学习模型）提取的特征表示。
2. **数据索引** ：
   * 为了快速检索，向量数据库使用特殊的索引结构来组织数据。这些索引结构通常基于空间索引技术，如KD树、球树、乘积量化（PQ）或倒排索引等，它们可以有效地在高维空间中进行搜索和查询操作。
   * 索引的建立是通过分析向量之间的空间关系，以优化检索效率。例如，可以将相似的向量分组存储，或者在多级索引中分层表示，从而加速查询时的搜索过程。
3. **相似性搜索** ：
   * 用户在查询时，会提供一个查询向量或一组查询向量。向量数据库通过索引快速找到与这个查询向量相似的向量。
   * 相似性通常通过计算向量之间的距离（如欧氏距离、余弦相似度等）来评估，向量越接近，它们之间的距离就越小，相似度越高。
4. **查询优化** ：
   * 高效的查询处理是向量数据库的重要特性之一。这些数据库通常包含优化算法，如近似最近邻搜索（ANN）技术，可以在接受小幅精度损失的情况下显著提高搜索速度。
   * 为了进一步提高查询性能，向量数据库也可能实现特定的硬件加速技术，如使用GPU或专用处理器来并行处理大量的向量计算。
5. **扩展性和弹性** ：
   * 现代向量数据库通常设计为可扩展的架构，可以横向扩展到多个服务器或云环境中，支持大规模的数据集和高并发的查询需求。
   * 通过分布式存储和计算，向量数据库可以处理从数百万到数十亿级别的向量数据，支持大数据和AI应用。

## 0.8 优秀的开源向量数据库项目

有许多优秀的开源向量数据库项目，每个项目都有其独特的特点和优势，非常适合用于不同规模和类型的AI应用。以下是一些知名的开源向量数据库项目：

1. **Milvus** ：
   * Milvus 是一个高性能的开源向量数据库，用于管理大规模的向量数据。它支持多种索引类型，可以高效处理海量数据，并支持在云原生环境中运行。Milvus 建立在一些流行的开源向量索引库上，如 Faiss、Annoy 和 HNSW。
2. **Faiss** ：
   * Faiss 是由 Facebook AI Research 开发的库，专注于高效相似性搜索和密集向量聚类。虽然它主要是作为一个库而不是完整的数据库系统，但它可以被集成到更大的系统中，用于高效的向量搜索任务。
3. **Annoy** ：
   * Annoy (Approximate Nearest Neighbors Oh Yeah) 是由 Spotify 开发的一个轻量级数据结构，专门用于内存中的近似最近邻搜索。它特别适用于实时查询场景。
4. **Nmslib** ：
   * Nmslib（非度量空间库）是一个高效的跨平台相似性搜索库和一个评估相似性搜索方法的工具包。它支持多种距离测量方法，并提供高性能的查询效率。
5. **Qdrant** ：
   * Qdrant 是一个开源的向量搜索引擎，提供高性能搜索和灵活的数据过滤。它用 Rust 编写，保证了高性能和安全性，特别适合需要同时处理向量数据和其他类型数据（如文本或图像）的应用。
6. **Weaviate** ：
   * Weaviate 是一个基于图的向量搜索引擎，支持GraphQL和RESTful API。它可以自动处理向量化，并提供丰富的数据连接功能，适用于构建复杂的数据关系网络。
7. **Vespa** ：
   * Vespa 是由 Yahoo 开发的大规模分布式文本搜索和查询处理系统。它支持实时索引和多种形式的数据查询，包括基于向量的搜索，适合动态数据集。
8. **Pinecone** ：
   * 虽然不是完全开源，但 Pinecone 是一个即服务（SaaS）形式的向量数据库，专门设计用于在生产环境中进行向量搜索。它提供易于使用的API和无缝的扩展能力，非常适合需要快速部署和高可扩展性的企业应用。

这些项目各有所长，选择哪个最合适取决于你的具体需求，例如数据规模、查询速度要求、开发环境和预算等因素。选择前，最好能够对这些工具进行详细的评估和对比。

**Milvus 是什么？** 

Milvus 是一款专门为存储、索引和管理由深度神经网络和其他机器学习模型生成的大量嵌入向量而设计的向量数据库。它能够在万亿级别上索引向量，与传统关系数据库不同，Milvus 从底层设计就是为了处理从非结构化数据转换来的嵌入向量。

**Milvus 的工作流程** 

Milvus 的工作流程包括数据的输入、向量化处理、索引创建和向量的相似性搜索。用户可以通过API将数据插入Milvus，然后执行基于向量的搜索操作，以找到与查询向量最相似的结果。

**为什么选择 Milvus？** 

1. 在处理大规模数据集进行向量搜索时，表现出高性能。
2. 提供开发者优先的社区支持，包括多语言支持和工具链。
3. 即使在中断事件中也能保持云扩展性和高可靠性。
4. 通过将标量过滤与向量相似性搜索相结合，实现混合搜索。

**支持的索引类型和相似度度量** 

Milvus 支持多种索引类型，主要使用近似最近邻搜索（ANNS）算法，如FLAT、IVF\_FLAT、IVF\_SQ8等。在相似度度量方面，常用的度量包括欧氏距离（用于计算机视觉）和内积（用于自然语言处理）。

**Milvus 的应用案例** 

Milvus 支持多种应用场景，包括图像相似性搜索、视频相似性搜索、音频查询、推荐系统、问答系统等。通过将数据转换为向量，并利用Milvus进行高效搜索，能够极大地提升应用性能和用户体验。

**Milvus 的设计架构** 

Milvus 是一种云原生的向量数据库，设计上将存储与计算分离，所有组件均为无状态设计，提高了系统的弹性和灵活性。系统分为访问层、协调器服务、工作节点和存储四个层级，每个层级各司其职，确保系统高效运行。

通过上述概览，您可以了解到Milvus的核心功能、设计理念及其在现代数据处理中的应用价值。

## 0.10 如何使用 Docker Compose 安装 Milvus Standalone

本主题介绍了如何使用 Docker Compose 安装 Milvus 单机版。

**安装前提** 

1. 检查您的机器上是否安装了 Docker 和 Docker Compose。
2. 在安装 Milvus 之前，检查硬件和软件的需求。
3. 对于使用 MacOS 10.14 或更高版本的用户，设置 Docker 虚拟机（VM）最少使用 2 个虚拟 CPU 和 8 GB 初始内存，否则安装可能会失败。

**安装步骤** 

1. **下载 YAML 文件**  
手动或使用以下命令下载 `milvus-standalone-docker-compose.yml` 并将其保存为 `docker-compose.yml`:  

```
wget https://github.com/milvus-io/milvus/releases/download/v2.4.0/milvus-standalone-docker-compose.yml -O docker-compose.yml

```

2. **启动 Milvus**  
在包含 `docker-compose.yml` 的目录中，运行以下命令以启动 Milvus:  

```
sudo docker compose up -d

```
  
如果上述命令运行失败，请检查系统是否安装了 Docker Compose V1。如果是，请根据本页面的说明迁移到 Docker Compose V2。
3. **验证安装**  
检查容器是否正在运行:  

```
sudo docker compose ps

```
  
启动后，应该会有三个 Docker 容器正在运行，包括 Milvus 单机服务及其两个依赖。
4. **连接到 Milvus**  
验证 Milvus 服务器监听的本地端口。请替换容器名称为您自己的容器名称:  

```
docker port milvus-standalone 19530/tcp

```
  
接下来，可以参考 Hello Milvus 来运行示例代码。
5. **停止 Milvus**  
要停止 Milvus 单机版，请运行:  

```
sudo docker compose down

```
  
若要在停止 Milvus 后删除数据，请运行:  

```
sudo rm -rf volumes

```


## 0.11 连接到您的 Milvus 集群并执行 CRUD 操作

**开始之前** 

* 您已安装 Milvus 单机版或 Milvus 集群。
* 您已安装首选的 SDK。可以选择多种语言，包括 Python、Java、Go 和 Node.js。

**Hello Milvus** 

为了确认您的 Milvus 实例运行正常并且 Python SDK 设置正确，请首先下载 `hello_milvus.py` 脚本。您可以使用以下命令进行下载：


```
wget https://raw.githubusercontent.com/milvus-io/milvus-docs/v2.4.x/assets/hello_milvus.py

```


接下来，更新脚本中的 `uri` 参数为您的 Milvus 实例地址。更新后，使用以下命令运行脚本：


```
python hello_milvus.py

```


如果脚本执行没有返回任何错误信息，您的 Milvus 实例运行正常，Python SDK 也正确安装。

**连接到 Milvus** 

获取集群凭证或 API 密钥后，您可以开始连接到 Milvus。


```
from pymilvus import MilvusClient, DataType

# 设置 Milvus 客户端
client = MilvusClient(
    uri="http://localhost:19530"
)

# 如果您的 Milvus 实例启用了身份验证，应在初始化 MilvusClient 时添加 token 参数

```


**创建集合** 

在 Milvus 中，您需要在集合中存储向量嵌入。所有存储在一个集合中的向量嵌入共享相同的维度和用于测量相似性的距离度量。您可以通过以下方式创建集合：

**快速设置** 


```
# 快速创建集合
client.create_collection(
    collection_name="quick_setup",
    dimension=5
)

```


**自定义设置** 


```
# 创建自定义集合
schema = MilvusClient.create_schema(
    auto_id=False,
    enable_dynamic_field=True
)

schema.add_field(field_name="my_id", datatype=DataType.INT64, is_primary=True)
schema.add_field(field_name="my_vector", datatype=DataType.FLOAT_VECTOR, dim=5)

index_params = client.prepare_index_params()
index_params.add_index(field_name="my_vector", index_type="AUTOINDEX", metric_type="IP")

client.create_collection(
    collection_name="customized_setup",
    schema=schema,
    index_params=index_params
)

```


**插入数据** 


```
# 准备数据
data = [
    {"id": 0, "vector": [0.358, -0.602, 0.184, -0.263, 0.903], "color": "pink_8682"},
    # 添加更多数据点...
]

# 插入数据
res = client.insert(
    collection_name="quick_setup",
    data=data
)

print(res)

```


**相似性搜索** 


```
# 准备查询向量
query_vectors = [[0.042, 0.014, -0.028, -0.013, 0.010]]

# 开始搜索
res = client.search(
    collection_name="quick_setup",
    data=query_vectors,
    limit=3
)

print(res)

```


**删除数据和集合** 


```
# 通过 ID 删除实体
client.delete(
    collection_name="quick_setup",
    ids=[0, 1, 2]
)

# 删除集合
client.drop_collection("quick_setup")

```

## 0.12 嵌入功能

Milvus 是一款专为大规模嵌入向量的存储、索引和管理而设计的向量数据库。它提供了内置的嵌入功能，可以与流行的嵌入提供者一起使用，帮助用户简化数据准备和向量搜索过程。

Milvus 支持多种类型的嵌入，包括密集嵌入和稀疏嵌入：

* **密集嵌入** ：大多数嵌入模型将信息表示为数百到数千维的浮点向量，这些向量称为“密集”向量，因为大部分维度都有非零值。
* **稀疏嵌入** ：与密集嵌入相对，稀疏嵌入的输出向量大部分维度为零，这些向量通常维度更高，由文本语料库的词汇大小决定。稀疏向量可以通过深度神经网络或文本语料的统计分析生成。

以下是一些主要的嵌入模型类型和来源：

* **OpenAI** （API, 密集）
* **Sentence Transformer** （开源, 密集）
* **BM25** （开源, 稀疏）
* **Splade** （开源, 稀疏）
* **BGE M3** （混合, 开源）

### 0.12.1 示例

1. **生成密集向量** ：使用默认的嵌入功能（例如 all-MiniLM-L6-v2 句子转换器模型）生成文档的密集向量。  

```
from pymilvus import model
ef = model.DefaultEmbeddingFunction()
docs = ["Artificial intelligence was founded as an academic discipline in 1956."]

print("Embeddings:", embeddings)

```

2. **同时生成密集和稀疏向量** ：使用 BGE M3 混合模型嵌入文本到密集和稀疏向量，并使用它们检索相关文档。  

```
from pymilvus.model.hybrid import BGEM3EmbeddingFunction
bge_m3_ef = BGEM3EmbeddingFunction()
docs_embeddings = bge_m3_ef(docs)

```

3. **生成稀疏向量** ：使用 BM25 模型为查询和文档生成稀疏嵌入。

```
from pymilvus.model.sparse import BM25EmbeddingFunction
```

这些示例展示了如何利用 Milvus 和各种嵌入模型来处理和搜索高维向量数据，从而在多种应用场景中提高信息检索和相似性搜索的效率。

### 0.13.2 实例化 OpenAI 嵌入功能


### 0.13.3 参数说明

## 0.14 案例实战

本案例将 OpenAI 的嵌入 API 与向量数据库 Milvus 集成，以在图书标题上执行搜索。许多现有的图书搜索解决方案（例如公共图书馆使用的）依赖于关键词匹配，而不是对标题内容的语义理解。利用训练好的模型表示输入数据被称为语义搜索，这可以扩展到各种基于文本的用例，包括异常检测和文档搜索。

### 0.14.1 开始前的准备

你需要从 OpenAI 网站获取一个 API 密钥，并确保已启动 Milvus 实例。

### 0.14.2 准备数据

我们将使用 CSV 文件中的图书标题作为例子。首先，创建一个函数从 CSV 文件中加载图书标题：


```
import csv

def csv_load(file):
    with open(file, newline='') as f:
        reader = csv.reader(f, delimiter=',')
        for row in reader:
            yield row[1]

```


### 0.14.3 使用 OpenAI 和 Milvus 搜索图书标题

首先，确保已下载并保存含有图书标题的 CSV 文件。然后，设置 Milvus 数据库，并为使用案例建立集合和索引。以下是主要步骤：

1. 连接到 Milvus 服务器并创建一个新的集合：  

```
from pymilvus import connections, utility, FieldSchema, CollectionSchema, DataType, Collection

connections.connect(host='localhost', port='19530')
if utility.has_collection('title_db'):
    utility.drop_collection('title_db')

fields = [
    FieldSchema(name='id', dtype=DataType.INT64, is_primary=True, auto_id=False),
    FieldSchema(name='title', dtype=DataType.VARCHAR, max_length=200),
    FieldSchema(name='embedding', dtype=DataType.FLOAT_VECTOR, dim=1536)
]
schema = CollectionSchema(fields=fields, description='Title collection')
collection = Collection(name='title_db', schema=schema)

```

2. 为集合创建索引：  

```
index_params = {
    'index_type': 'IVF_FLAT',
    'metric_type': 'L2',
    'params': {'nlist': 1024}
}
collection.create_index(field_name="embedding", index_params=index_params)

```

3. 将数据嵌入并插入到 Milvus 中：  

```
import time
from openai import OpenAI

client = OpenAI()
client.api_key = 'YOUR_API_KEY'

def embed(text):
    response = client.embeddings.create(input=text, model='text-embedding-3-small')
    return response['data'][0]['embedding']

for idx, text in enumerate(random.sample(list(csv_load('./content/books.csv')), k=100)):
    ins = [[idx], [text[:198] + '..' if len(text) > 200 else text], [embed(text)]]
    collection.insert(ins)
    time.sleep(3)  # 控制请求频率

```

4. 加载集合并执行搜索：  

```
collection.load()

def search(text):
    query_embedding = embed(text)
    results = collection.search(
        data=[query_embedding],
        anns_field="embedding",
        param={"metric_type": "L2"},
        limit=5,
        output_fields=['title']
    )
    return [(hit.id, hit.score, hit.entity.get('title')) for hit in results[0]]

# 测试搜索
search_terms = ['self-improvement', 'landscape']
for term in search_terms:
    print(f'Search term: {term}')
    for result in search(term):
        print(result)
    print()

```


这个示例展示了如何使用 OpenAI 的嵌入 API 和 Milvus 进行图书标题的语义搜索，这种方法不仅提高了搜索的相关性，而且扩展了搜索的可能性，使其不再局限于简单的关键词匹配。
